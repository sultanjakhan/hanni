# Hanni agent instructions

Отвечай кратко и отделяй подтверждённые факты от выводов. GitHub Issues — источник истины для текущих кейсов и решений.

## Одна интеграционная ветка

- `main` — единственная записываемая интеграционная ветка Hanni.
- Не создавай новые ветки. Существующие non-main refs считаются read-only источниками для выборочного переноса до их проверки и удаления владельцем.
- В каждый момент только одна явно назначенная вкладка является integration owner. Только она может менять source checkout, выполнять `git add`, commit, merge/cherry-pick, push, tag или release.
- Worker-вкладки выполняют исследование и проверки read-only, затем передают владельцу выводы или патч; сами не коммитят и не публикуют изменения.
- Перед записью проверь локальный single-writer lock, `git status`, текущую ветку, HEAD и отсутствие незавершённой Git-операции. Если lock или владелец не определены, остановись и запроси назначение.
- Не используй `--no-verify`, не отключай hooks и не обходи single-writer guard.

## Сохранность истории

- Не выполняй `pull`, `reset`, `clean`, `checkout`, merge или rebase в checkout с неизвестным либо чужим WIP.
- Не сливай целиком старую ветку с несвязанной историей. Сначала сохрани recovery bundle/patch, затем переноси нужные изменения выборочно на `main`.
- Интегрируй по одному источнику за раз. После каждого переноса запускай релевантные тесты и фиксируй точный SHA результата.
