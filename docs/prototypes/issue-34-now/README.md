# Issue #34 — кликабельный прототип «Сейчас»

Статус: **EXPERIMENT**. Это отдельный fixture-driven прототип Option A, а не изменение production-интерфейса Hanni.

Прототип проверяет один сценарий: открыть Calendar, увидеть одно следующее действие, понять причину рекомендации и начать либо восстановиться после скрытия/ошибки. Карточка расположена после заголовка Calendar и до pane tabs.

## Запуск

Из корня репозитория:

```powershell
py -m http.server 4173 --directory docs/prototypes/issue-34-now
```

Затем открыть `http://127.0.0.1:4173/`. Если команда `py` недоступна, подойдёт `python -m http.server` с теми же аргументами.

Прототип не требует npm install, Tauri, базы данных или доступа к сети. Все данные синтетические и живут только в памяти вкладки; перезагрузка возвращает исходную рекомендацию.

Базовые light/dark цвета, типографика и радиусы основаны на текущих tokens `desktop/src/css/base.css`. Текстовые и action-цвета намеренно усилены до WCAG AA; композиция самой карточки остаётся проверяемой design-гипотезой.

## Что можно проверить

- `Начать` переводит рекомендацию в состояние `В работе`.
- `Пауза` возвращает ту же задачу как `Приостановлено`; `Продолжить` возобновляет её.
- `Завершить` сначала показывает `Завершаем…`, затем спокойное пустое состояние.
- `Не сейчас` скрывает рекомендацию только в текущей сессии; `Вернуть` восстанавливает её.
- `Уточнить` раскрывает причину и первый шаг. Escape сворачивает панель и возвращает фокус на кнопку.
- Переключатель `Сбой следующего действия` имитирует ошибку start/resume/pause/finish; retry повторяет то же действие с сохранённым контекстом.
- Панель `Управление прототипом` позволяет напрямую открыть loading, recommendation, clarified, dismissed, active, paused, finish pending, empty и error. Эта панель не является частью предлагаемого продукта.
- Кнопка темы показывает light/dark tokens без сохранения пользовательской настройки.

Ручной проход нужен на ширинах 1280, 760 и 640 px, с мышью и только клавиатурой. На 200% zoom не должно появляться горизонтальной прокрутки; при `prefers-reduced-motion: reduce` анимации сводятся к минимуму.

Исходный fingerprint для прототипа: `hanni@b7439fd4555b20da303cd66646c7b8deae7d77ae`, Windows desktop / Calendar. Исторический draft PR не принят как готовый дизайн и не копируется сюда.

Авторизованный handoff ограничивает решение одной карточкой `Сейчас`, одним кандидатом и обратимыми действиями. Критерий опровержения гипотезы: пользователь не находит действие за 10 секунд, не может объяснить рекомендацию после `Уточнить`, не восстанавливает скрытую карточку или теряет контекст после ошибки.

## Что этот прототип не доказывает

- Это не production-код: `desktop/src`, SQLite, Tauri IPC и ranking logic не подключены.
- Это не native/live evidence установленной Hanni. Актуального принятого native visual/accessibility report для #34 нет.
- Список canonical product-record IDs для handoff не был предоставлен; идентификаторы не выдуманы.
- Не решено, должно ли `Не сейчас` переживать reload или смену дня.
- Не решено, нужен ли reflection modal после `Завершить`.
- Не проверены реальные задержки, ошибки backend, screen reader и поведение на установленной Windows-сборке.
- Прототип не добавляет Home/dashboard, новую БД, Personal Ops, AFK/window monitoring, autostart или общий редизайн вкладок.

До production-реализации нужны отдельное решение по неизвестным выше и native UX/visual проверка установленной Hanni.
