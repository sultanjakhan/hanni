# Hanni encrypted relay v2

Сервер сохраняет зашифрованные изменения четырёх устройств, выдаёт возрастающий
`seq` и сообщает о новых данных через native WebSocket. Checkpoint заменяет старый
префикс журнала полным зашифрованным снимком; отключённый компьютер восстанавливает
его и дочитывает новый хвост. Обычная отправка не останавливается на время снимка.
Точный wire и правила восстановления: [CONTRACT.md](CONTRACT.md).

## Сохранность

Вставки и публикация выполняются в SQLite `transactionSync`; ACK и уведомления
выходят после `storage.sync()`. Монотонный `client_seq` и последнее точное ACK на
устройство сохраняются после очистки ciphertext. Старый курсор получает409
`checkpoint_required`, поэтому отсутствие удалённого префикса не выглядит успехом.

Части снимка неизменны. Публикация проверяет их число, размер, порядок SHA-256,
поколение и fencing epoch аренды. Сбой загрузчика не блокирует обычную отправку.
Предыдущие снимки имеют30мин grace; действующие read leases защищают загрузку от
очистки. Durable alarms очищают только заменённый префикс, просроченные staging и
старые неприкреплённые снимки небольшими транзакциями.

Серверу передаются только конверты XChaCha20-Poly1305, непрозрачные идентификаторы,
порядковые номера, размеры и хеши. Он не знает ключ расшифрования и не может
доказать корректность содержимого снимка. Клиент проверяет AEAD, полноту и профиль,
атомарно объединяет снимок с SQLite и сохраняет dirty/outbox, soft-deletes,
незавершённые фрагменты и applied floors. Нельзя переиспользовать ключ между
разными пользователями или relay.

Все запросы требуют HTTPS и `Authorization: Bearer`; токены в URL отвергаются.
`HANNI_DEVICE_TOKEN_HASHES` содержит JSON `opaque_device_id -> SHA256(token_string)`.
До8 уникальных32-байтовых токенов в canonical base64url; реальные значения в этот
каталог не записываются. Native WebSocket умеет Authorization header, браузерный
конструктор WebSocket — нет. Журналы с credentials, ciphertext, health rows и raw
exceptions отсутствуют; observability выключена в конфигурации.

## Конечные пределы

| Ресурс | Локальный предел |
| --- | ---: |
| HTTP body / ciphertext c tag | 96KiB /64KiB |
| Страница |32 записи и менее примерно512KiB |
| Неочищенный журнал |128MiB /100000 сохранённых пакетов |
| Один снимок |128MiB canonical envelope bytes /4096 частей |
| SQLite + резерв незагруженных снимков |768MiB |
| Авторизованные запросы и alarms за UTC сутки |15000 |
| Новые обычные пакеты /bytes за UTC сутки |4000 /16MiB |
| Checkpoint bytes за UTC сутки |128MiB |
| Консервативные write units /GC payload rows в сутки |80000 /10000 |

Резерв незагруженной части снимка не может быть занят обычным журналом. Ошибки429
с `Retry-After` и507 сохраняют подтверждённые данные; клиент оставляет outbox и
повторяет с задержкой. Очистка освобождает старые версии, но не делает бесконечной
историю уникальных медицинских записей. Снимок больше128MiB требует дальнейшего
решения до достижения предела; автоматического удаления истории нет.

SQLite DO доступен на Workers Free. В официальной странице limits есть разные
формулировки10GB общей таблицы и1GB Free в FAQ; здесь выбран меньший1GB, с запасом
до768MiB. Эти ограничения приложения не подтверждают тариф аккаунта и не являются
гарантией отсутствия платы на уже платном аккаунте. На Free превышение квот
провайдера вызывает ошибки. Код не меняет тарифы, не покупает ресурсы и не открывает
порты маршрутизатора.

## Интеграция и проверка

Это пакет исходников; его наличие не означает deployment или подключение устройств.
`wrangler.jsonc` использует свежий worker/DO namespace `hanni-personal-relay-v2`.
Старый v1 SQLite формат отвергается с503 `protocol_migration_required`; миграция и
удаление старого DO не выполняются. Native client должен использовать v2 AAD и
монотонный `client_seq` до переключения endpoint.

Зависимости закреплены: Wrangler4.129.0, его Miniflare5.20260903.0-alpha,
workerd1.20260903.1, Node>=22. Tests загружают Miniflare из установленного пакета,
`HANNI_MINIFLARE_MODULE` или из соседнего изолированного `cloudflare-tooling`.
Запуск: `node --test test/*.test.mjs`. Persistent SQLite fixtures находятся только
в игнорируемом `test-state/`, токены синтетические и генерируются в памяти.

29/29 тестов прошли в настоящем локальном workerd/SQLite: потеря ACK,
идемпотентность после GC, конкурирующие finalize, аренды и их замена, сохранность
нового хвоста, read lease при смене поколения, лимиты, восстановление runtime,
bounded GC, самостоятельные durable alarms и освобождение места восьми поколений.
Из них19 checkpoint-тестов; предыдущие10 тестов транспорта адаптированы к
`client_seq` и сохранены отдельно.
Синтетические opaque bytes проверяют транспорт, а не клиентскую криптографию.
Тесты не доказывают работу установленных Android/Windows/Mac, Doze/force-stop,
Samsung Health→Health Connect, автозапуск или региональный deployment.
